## 已验证的模型定义

8 个 link（含无几何的 world）、7 个 joint，其中 1 个 fixed、6 个 revolute。
规划组为 `dummy_arm`，链为 `base_link → link6_1_1`，变量按
`Joint1…Joint6` 排列。无额外 `<end_effector>` 组、无独立 TCP/tool0；
`link6_1_1` 仅为当前链末端，不是经过标定的工具中心。

| 关节 | 局部关节坐标系中的轴 | 下/上限 rad | 速度 rad/s | effort（URDF） |
|---|---|---|---|---|
| Joint1 | (0,0,-1) | -3.14 / 3.14 | 3.15 | 150 |
| Joint2 | (-1,0,0) | -3.14 / 3.14 | 3.15 | 150 |
| Joint3 | (-1,0,0) | -3.14 / 3.14 | 3.15 | 150 |
| Joint4 | (0,-1,0) | -3.14 / 3.14 | 3.15 | 150 |
| Joint5 | (-1,0,0) | -3.14 / 3.14 | 3.15 | 150 |
| Joint6 | (0,-1,0) | -3.14 / 3.14 | 3.15 | 150 |

证据：描述 Xacro 的对应 `<joint>` 与 static_audit.json。
这些是软件源文件值，**不是已验证的机械安全范围/额定力矩**。
根 world 通过 world_joint 固定到 base_link，rpy=(π,π,0)，原值保留；
不能另发一个 identity world→base_link TF，也不能凭显示方向自行翻转模型。
7 个有形连杆各自使用同一个 STL 作为 visual/collision，缩放均为 0.001；
碰撞 Mesh 合计 53,108 个三角形，未进行性能测试；完整三角形数和原始网格边界已记录在 JSON，未做几何简化或 CAD 一致性判断。

## 本轮数学与 API

本轮没有规划或路径优化算法。C++ 诊断输入为 URDF/SRDF 与六维关节向量
`q∈R⁶`，输出为状态有效性、接触对和末端变换诊断。
正运动学 `T_world,tip(q)=T_world,base ∏ T_i(q_i)`，矩阵为 4×4。
比较 `||T(q+0.1e_i)-T(q)||_F>1e-8` 只检查状态变化能传播到末端，
不是位姿精度指标，也没有把角度和长度混成实验路径代价。

`RobotModelLoader` 读取模型语义；`getJointModelGroup` 返回规划变量集合；
`RobotState::update` 更新 FK；`satisfiesBounds` 检查模型位置限位；
`PlanningScene::checkSelfCollision` 使用现有 SRDF 的允许碰撞矩阵检查自碰撞。
仅 home/reset 两个姿态通过也不能验证整个碰撞豁免矩阵或连续路径。

API 已对照 MoveIt Jazzy 分支声明；这不等于验证用户 Ubuntu 安装版本。

STL 结构/数值及 Python/YAML 语法已检查。没有进行几何碰撞计算。

## Debug 与回退

- 包发现/构建失败：先查 package 名、source 环境、rosdep 和首个编译错误。
- Xacro 失败：查包资源与 initial_positions_file，不改机器人关节来绕过。
- RViz 缺 Mesh：查 robot_description、安装路径、TF 和资源报错；保留日志。
- home/reset 碰撞：根据输出 contact 对定位 geometry/姿态/SRDF；
  不为得到 PASS 而扩大 disable_collisions。
- 切换 Ubuntu 后先运行 D0，回传 build/model_check/rviz 日志和截图，再人工验收。
- 上游原文件保持只读；`upstream_changes.diff` 和逐文件双哈希可以复核改动；
  回退通过 Git 新提交或重新引入锁定 SHA，不覆盖来源资料。
